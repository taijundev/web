Amplitude Browser SDK 2 · De-identification Option 2

Amplitude Web SDK Playground

방안2(User ID 가명화 전송) 가 적용된 테스트 페이지입니다. 입력한 User ID 원문은 페이지 자체 Session Store 에만 남고, Amplitude 에는 가명화된 값만 전송됩니다. 실제로 api2.amplitude.com/2/httpapi 로 나가는 요청 본문과 응답을 아래 로그에 그대로 보여주므로 DevTools 없이도 무엇이 전송됐는지 확인할 수 있습니다.

고객사 전달 샘플 범위 — 이 페이지의 스크립트는 네 블록으로 나뉘어 있습니다. [C] Amplitude 연동 블록(AmplitudeAnalytics 클래스)만 그대로 발췌하면 샘플 코드가 됩니다. [B] 고객사 구현 영역(SessionStore, Pseudonymizer)은 고객사 환경에 맞게 교체할 부분이고, [D] 테스트 콘솔 UI 는 이 페이지 전용이라 샘플에 포함되지 않습니다.

01현재 상태

02User ID 설정

입력한 원문 은 웹 페이지가 자체 관리하는 Session Store (localStorage["playground_app_user_id"]) 에 저장되고, Amplitude 에는 가명화된 값만 setUserId() 로 전달됩니다. 가명 ID 는 SDK 쿠키에 캐싱되어 새로고침 후에도 유지됩니다. 01 섹션에서 원문(Session Store)과 가명 ID(user_id)를 나란히 확인할 수 있습니다.

세 버튼은 서로 다른 저장소를 건드립니다 — Amplitude Reset 은 amplitude.reset() 으로 SDK 쿠키만(user_id 제거, device_id 재발급), Session Store 비우기 는 페이지 자체 localStorage 만, 최초 실행 플래그 초기화 는 마이그레이션 플래그만 지우고 새로고침합니다(분기 A 재현용).

03이벤트 전송

비워 두면 properties 없이 전송합니다. JSON 형식이 아니면 전송하지 않고 오류를 표시합니다.

04전송 로그

아래 로그의 REQUEST 블록은 SDK 가 실제로 네트워크로 내보낸 요청 본문 그대로입니다. window.fetch 를 감싸 /2/httpapi 요청만 가로채 기록합니다.

이 페이지는 세션·페이지뷰·어트리뷰션 자동 수집은 켜 두되, 버튼 클릭·폼 입력 자동 수집은 꺼 두었습니다 — 테스트 버튼을 누르는 행위 자체가 이벤트로 잡히면 정작 확인하려는 이벤트가 로그에 묻히기 때문입니다. 그래서 [Amplitude] Page Viewed, session_start 는 보이지만 [Amplitude] Element Clicked 는 보이지 않습니다.
방안2 확인 포인트 — REQUEST 본문의 user_id 는 pseudo_ 로 시작해야 하며, 본문 어디에도 입력한 원문 문자열이 나타나지 않아야 정상입니다. 브라우저 찾기(⌘F / Ctrl+F)로 원문을 검색해 확인하세요.
